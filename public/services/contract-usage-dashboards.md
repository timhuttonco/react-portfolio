### Contract & Usage Dashboards

**Know exactly where you stand against every vendor contract, without logging into a single portal.**

Managing a portfolio of analytics and measurement platforms means managing a portfolio of contracts, each with its own billing cycle, usage limits, and reporting interface. Renewals sneak up, invoices arrive months after the fact, and by the time an overage shows up it's too late to act. I've built exactly this: a consolidated hub pulling usage data from multiple vendors (via API where available, or an automated CSV upload pipeline where it isn't) into a single, always-current view with month-on-month pacing against contract limits.

**Timeline:** 3–6 weeks, depending on number of vendors &nbsp;|&nbsp; **Format:** Built and delivered dashboard, with documentation

#### What's Included

- Requirements review across your current vendor contracts: billing cycles, usage limits, and available data access (API vs. manual export).
- A dashboard consolidating usage across all in-scope vendors into one view, with pacing logic showing whether you're on track against annual/contract-year limits.
- Automated data pipelines for API-based platforms; a simple upload pipeline for vendors that only offer manual exports.
- Month-on-month usage comparisons and early-warning flags as limits approach.
- Handover documentation covering how to add new vendors or adjust limits going forward.

#### Best Fit For

- Teams juggling several analytics, CDP, or measurement vendor contracts with different billing cycles.
- Anyone who has been surprised by an overage fee or a renewal deadline in the last 12 months.
- Organisations wanting a lightweight internal tool rather than manually checking multiple vendor portals every month.

#### What I'll Need From You

- A list of vendors in scope, along with contract terms and current access to each portal.
- A cloud project (GCP/Firebase or equivalent) to build the dashboard into, or willingness to set one up.
- Sign-off from whoever owns the underlying vendor relationships, since read access to billing/usage data is typically required.
