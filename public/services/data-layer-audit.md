### Data Layer Audit

**The foundation everything else is built on: if it's inconsistent, everything downstream inherits the problem.**

Most tracking issues don't start in GTM or GA4; they start in the dataLayer. Inconsistent naming, timing pushes that fire before the values they carry exist, values pushed as the wrong type, or the same event modelled three different ways across three different pages. This audit reviews your dataLayer structure on its own terms, before it ever reaches a tag.

**Timeline:** 3–5 days &nbsp;|&nbsp; **Format:** Report + walkthrough call

#### What's Included

- Full review of dataLayer naming conventions and structure across key page types and user journeys.
- Push timing review: confirming events fire after (not before) the data they reference is available.
- Consistency check across pages/sections built by different teams or at different times.
- Recommendations for a standardised, documented dataLayer schema going forward.
- A written report with examples of inconsistencies found and the fix for each.

#### Best Fit For

- Sites or apps built up over time by multiple teams or agencies, where nobody currently owns dataLayer consistency.
- Teams about to start a GA4, GTM, or server-side migration who want a clean foundation before they move.
- Anyone who has seen the same event tracked two different ways in two different reports and wants to know why.

#### What I'll Need From You

- Read access to the site/app in a staging or production environment.
- Read access to the GTM container, if one already exists.
- Sight of any existing dataLayer documentation (even informal notes count).
